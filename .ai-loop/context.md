Читается в начале каждой фазы. Лимит — две страницы. Полный контекст цикла
Telegram-интеграции — в `docs/final_vision/` (README.md — точка входа).

## Острые грани (сэкономят повтор ошибки)

- **`--paths` не видит объём диффа.** `classify_diff.py`: `collect_paths()` в
  режиме `--paths` жёстко возвращает `lines_changed = 0`, порог
  `lines_changed_over` там структурно не срабатывает. Перед коммитом — только
  `--worktree`/`--staged`/`--range`.
- **`.gitignore` с шаблоном без слэша матчит на любой глубине.** `build/` (без
  `/`) молча исключил `Tool/skills/build/SKILL.md` — на GitHub было 8 скиллов
  вместо 9, и `git status` этого не показывал. Исправлено на `/build/`.
- **`.size_ratchets.json` — НЕ runtime-шум, несмотря на внешний вид.** Это база
  принуждения shrink-only; `SizeRatchets._load_limits()` при отсутствии файла
  возвращает `{}` — храповики молча отключаются на свежем клоне. Остаётся под
  версионным контролем сознательно (в отличие от `.ai_workspace_state.json` и
  `Core/failures.jsonl`, которые сняты).
- **Даже два разрешённых файла в одном коммите могут требовать человека.**
  Эскалация `test_and_product_same_diff`: MEDIUM (зона T) + LOW (зона E) →
  HIGH → `require_human`. Один шаг плана = один коммит.
- **Telegram: `getUpdates` и `setWebhook` взаимоисключающие.** Long polling не
  требует публичного адреса и работает за NAT; webhook требует HTTPS с
  валидным сертификатом на портах 443/80/88/8443. Проверено по документации
  Bot API, не по спецификациям в `docs/`.
- **Репозиторий `VlaD-KH/Why_Ai` — публичный.** Секреты и Telegram ID
  оператора — только через ENV, никогда не в отслеживаемый файл.
- **Классовый API, покрытый тестами, не доказывает работоспособность CLI.**
  `Supervisor/launcher.py:121,123` содержал `type="str"` вместо `type=str` —
  argparse падал с `ValueError` до разбора аргументов, то есть внеполосный
  `--panic-stop` из командной строки не запускался вообще. Тесты были зелёные,
  потому что проверяли только `SupervisorLauncher` напрямую. Исправлено
  2026-08-21, добавлен `TestSupervisorLauncherCLI` (запуск через subprocess).
  Урок общий: если у модуля есть CLI, тест обязан идти через CLI.

## Острые грани — цикл самоэволюции (2026-08-22)

- **Цикл разомкнут: работает 1 звено из 9.** Нет предложителя (ни одного вызова
  модели в продакшен-коде; `changed_files` в `EvolutionDaemon.py:141` —
  захардкоженный литерал), нет применителя (`CommitGate.verify_and_merge`
  возвращает литерал без git-команд). Работает только `WorktreeSandbox`.
  Разбор — `docs/final_vision/06-self-evo-audit.md`.
- **Кнопка «Evolve» — гарантированный no-op.** `IdempotencyGate` читает
  `refactor_plan["patterns"]`/`["total_failures"]`, а `generate_refactor_plan()`
  их не возвращает → всегда `IDEMPOTENCY_REJECTED`. `server.py:284` зовёт без
  `force`. Проверено запуском.
- **Режимы `[self_evo]`/`[prod_evo]` ни на что не влияют.** `switch_mode()`
  пишет JSON, который никто не читает для принятия решений. `classify_diff.py`
  не содержит понятия режима. Строить надо не два режима, а один конвейер:
  предложить → изолировать → оценить → применить → записать.
- **Память агента лежит в зоне R.** `identity.md`, `scratchpad.md`,
  `failures.jsonl` внутри `Core/` — поэтому запись в собственную память есть
  дифф защищённого кода. У Ouroboros data-root вынесен за репозиторий, и
  вопрос не возникает. Проблема топологическая, не политическая.
- **Гейт стоит не на том конце конвейера.** `protected_paths.yaml` гейтит дифф,
  значит агент не может даже *авторствовать* предложение по `Core/`. У Ouroboros
  режим `pro` позволяет оставить правку на диске, но публикация требует
  reviewed-commit — разделение propose/publish.
- **Дедлок TDD.** Кворум требует тест в том же диффе, классификатор эскалирует
  T+не-T до `require_human`. «Код плюс его тест» по построению всегда требует
  человека.
- **`QuorumReviewer.py:42` регистрозависим.** На NTFS `supervisor/launcher.py`
  минует защиту `Supervisor/`, попадая в тот же файл.
- **Тесты этого не ловят по построению.** `test_evolution_daemon.py:38`
  принимает любой исход включая провал; `:20` подаёт форму словаря, которую
  реальный код никогда не производит.
