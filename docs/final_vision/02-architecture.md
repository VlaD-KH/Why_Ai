# 02 — Рекомендуемая архитектура

Опирается на `01-audit.md`. Все решения здесь выбраны так, чтобы **не потребовалось
править `Supervisor/`** и не сломать инвариант stdlib-only.

---

## Принцип, из которого следует всё остальное

> Алерт — это **следствие** события, а не часть механизма, который событие порождает.

Спецификация встраивала доставку алертов **внутрь** гейта (`Supervisor/launcher.py`).
Из этого автоматически следовали: правка зоны R, новая сторонняя зависимость в
неизменяемом ядре, `asyncio` внутри синхронного супервизора и риск, что сбой
Telegram-транспорта повлияет на работу самого гейта.

Рекомендуемый подход разворачивает зависимость: гейты **уже** публикуют события,
мост их **читает**. Супервизор не знает про Telegram и не должен.

```
┌──────────────────────────────────────────────────────────────┐
│  Supervisor/ (зона R) — НЕ ИЗМЕНЯЕТСЯ НИ ОДНОЙ СТРОКОЙ       │
│  launcher.panic_stop() · CommitGate · QuorumReviewer          │
└───────────────────────────┬──────────────────────────────────┘
                            │ (уже существует)
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  Core/server.py — broadcast_event()  ·  GET /api/events/stream│
│  POST /api/panic уже вызывает panic_stop() И вещает событие   │
└───────────────────────────┬──────────────────────────────────┘
                            │  SSE (чтение)          ▲ POST /api/panic
                            ▼                        │ (с проверкой статуса)
┌──────────────────────────────────────────────────────────────┐
│  Tool/connectors/  (зона R — требует подписи человека)        │
│    telegram_connector.py  — реальный I/O через urllib.request │
│    telegram_bridge.py     — SSE-подписчик + long polling      │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTPS (исходящий, за NAT)
                            ▼
                    [ Telegram Bot API ]
                            │
                            ▼
                    [ Оператор в Telegram ]
```

---

## Решение 1. Доставка алертов — подписка на SSE, а не хук в Supervisor

`Core/server.py:55` уже содержит `broadcast_event(event_type, data)` с фан-аутом в
`EVENT_SUBSCRIBERS`, и уже вещает: `panic_stop`, `worktrees_pruned`,
`evolution_cycle`, `mode_changed`, `db_synced`, `dvpn_*`.
Публичный эндпоинт — `GET /api/events/stream` (строка 231).

Ключевое: **`POST /api/panic` (строка 268) сам вызывает `SupervisorLauncher.panic_stop()`
и сразу шлёт `broadcast_event("panic_stop", …)`.** Паника уже эмитится наружу —
мосту достаточно подписаться. Ноль строк в `Supervisor/`.

**Покрытие четырёх заявленных триггеров без правки зоны R:**

| Триггер из спецификации | Источник, который уже существует |
|---|---|
| `PANIC` (Exit Code 10) | событие `panic_stop` в SSE |
| `CRITICAL` (падение тестов) | `Core/failures.jsonl` через `MetaOverPatch.record_failure`; файл в `exclusions` политики, дописывание не порождает гейт |
| `CONSENSUS` (вето кворума) | возвращаемое значение `QuorumReviewer.review_diff()` → `{diff_sha256, quorum_decision, veto_reasons}`; вызывать снаружи, не править внутри |
| `SIZE_WARN` (храповики) | `SizeRatchets` + `antigravity_debug.log`, куда `launcher.py:20-28` уже пишет через `FileHandler` |

Ни один не требует изменения `Supervisor/`.

## Решение 2. Транспорт — stdlib `urllib.request`, а не `httpx`

Проект действительно stdlib-only (единственное исключение — `yaml` в `try/except`
с fallback). Манифестов зависимостей нет ни одного. Введение `httpx` заставило бы
создать `requirements.txt`/`pyproject.toml` — а это **зона I, HIGH, require_human**,
плюс потеря свойства «клонировал и запустил».

`urllib.request` + `json` покрывают всё нужное: `POST /sendMessage`,
`GET /getUpdates` с таймаутом. Telegram Bot API — обычный HTTPS+JSON.

## Решение 3. Бот на long polling, а не webhook

Проверено по документации Bot API:

| | Публичный HTTPS-эндпоинт | Работает за NAT |
|---|---|---|
| `getUpdates` (long polling) | **не нужен** | **да** |
| `setWebhook` | обязателен, порты 443/80/88/8443 | нет |

Методы взаимоисключающие. Long polling даёт работающего бота **сегодня, на машине
оператора, без туннелей и хостинга**. Это и есть причина, по которой Mini App
вынесен в отдельную фазу: он требует HTTPS, а бот — нет.

## Решение 4. Авторизация — обязательная и fail-closed

Текущий `handle_incoming_command` **не имеет параметра `user_id` вообще**. Это
надо исправить в первую очередь: команда `/panic` без авторизации опаснее, чем
отсутствие Telegram-интеграции.

```
операторы читаются из ENV (WHY_AI_TELEGRAM_OPERATORS, список ID через запятую)
       │
       ├─ список пуст или переменная не задана  →  отклонять ВСЁ (fail-closed)
       ├─ user_id отсутствует в апдейте          →  отклонять
       ├─ user_id не в списке                    →  отклонять + запись в лог
       └─ user_id в списке                       →  выполнять
```

**ID оператора не хранится в репозитории** — репозиторий публичный. В
`why_ai_config.yaml` допустимо только **имя** переменной окружения, как это уже
сделано для `${GITHUB_TOKEN}` в `Tool/mcp_config.json`.

## Решение 5. Правильные эндпоинты, с проверкой кода ответа

| Команда | Спецификация (не работает) | Правильно |
|---|---|---|
| `/panic` | `POST /api/control/panic` → 404, **статус не проверяется** | `POST /api/panic`, **обязательно проверить HTTP-статус** и сообщить оператору фактический результат |
| `/status` | `GET /api/events/stream` (бесконечный поток → таймаут) | `GET /api/status` |

Правило, вытекающее из аудита: **никогда не рапортовать об успехе операции по
факту отправки запроса.** Сообщение «Инициируется Exit Code 10» при 404 в ответ —
худший из возможных отказов, потому что оператор считает систему остановленной.

## Решение 6. Размещение — `Tool/connectors/`, зона R, и это правильно

Соблазн положить мост в `Eye/` понятен: это единственная зона, где агент может
писать автономно (LOW/auto). Но `protected_paths.yaml` описывает зону E как
«UI/telemetry carrying no runtime authority of their own». Процесс, читающий
секреты и открывающий исходящие сетевые соединения, там — **вектор обхода
политики, а не решение**.

Правильное размещение:

| Файл | Зона | Почему так |
|---|---|---|
| `Tool/connectors/telegram_connector.py` | R | уже существует; коннектор с внешними эффектами |
| `Tool/connectors/telegram_bridge.py` (новый) | R | читает секреты, шлёт наружу — обязан требовать подписи |
| `Eye/telegram_mini_app.html` (фаза 3) | E | действительно только UI, без секретов |
| `tests/test_telegram_connector.py` | T | тесты |

То, что это требует человеческого одобрения, — **не препятствие, а корректная
работа контура**. Компонент, управляющий рубильником `/panic`, и должен проходить
через человека.

## Явно отвергнутые альтернативы

| Вариант | Почему отвергнут |
|---|---|
| Хук `trigger_telegram_alert` в `Supervisor/launcher.py` | зона R + жёсткое вето `QuorumReviewer.py:42` + Принцип 1 BIBLE; вставляется в несуществующую функцию `run_reviewed_commit_gate`; `asyncio` не импортирован |
| Второй MCP-сервер на `mcp.server.fastmcp.FastMCP` | конфликтует с собственным `FastMCPServer`; `async def`-инструменты несовместимы с синхронным `call_tool:115` |
| `httpx` как транспорт | ломает stdlib-only; тянет создание манифеста зависимостей (зона I) |
| `setWebhook` | требует публичного HTTPS; не нужен, пока есть long polling |
| Токен в `Tool/mcp_config.json` | файл коммитится, репозиторий публичный; противоречит собственному принципу спецификации |
| Мост в `Eye/` ради авто-разрешения | формально пройдёт классификатор, по существу обойдёт смысл зоны E |
| `pytest` в гейте | проект на `unittest`; без `cwd=` даёт ImportError → ложный CRITICAL и ложный `exit(10)` |

## Что остаётся нерешённым и требует человека

1. **`Supervisor/launcher.py:121,123` — `type="str"` вместо `type=str`.** CLI не
   запускается вообще, то есть внеполосный рубильник из командной строки сейчас
   не работает. Это подрывает саму предпосылку внеполосного управления. Зона R —
   агент починить не может.
2. **Две дыры в BIBLE**: нет принципа о хранении секретов и нет принципа о сетевом
   доступе. Сейчас «Zero PII» держится только на документах зоны E.
3. **Аутентификация на `POST /api/panic`** отсутствует, при `Access-Control-Allow-Origin: *`.
4. **HTTPS для Mini App** — туннель, хостинг или Test Environment. Решение отложено
   вместе с фазой 3.
