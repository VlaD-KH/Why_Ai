## Фаза 3 — Telegram Mini App (требует решения по HTTPS)

*Цель: телеметрия и кнопка `/panic` в интерфейсе Telegram.*

Зависимости: Фазы 1–2 **и** решение оператора по HTTPS-доступу.

> **Блокер, который спецификации игнорируют.** Telegram в production принимает
> только **HTTPS с валидным сертификатом**; `http://127.0.0.1:8765` в Mini App
> не откроется. HTTP и прямые IP допустимы лишь в Test Environment.
> Варианты: туннель (cloudflared/ngrok), реальный хостинг, либо Test Environment
> для разработки. Это решение человека, не агента.

- [ ] **3.0.** Выбрать способ HTTPS-доступа *(решение оператора)*
- [ ] **3.1.** `Eye/telegram_mini_app.html` — зона E, **без секретов**,
      только чтение SSE. Vanilla JS, как существующий `dashboard.html`
- [ ] **3.2.** Валидация `initData` по HMAC-SHA-256 на стороне бэкенда
      (`initDataUnsafe` доверять нельзя)
- [ ] **3.3.** Кнопка `web_app` в ответе на `/start`
- [ ] **3.4.** Аутентификация на `POST /api/panic` — сейчас её нет при
      `Access-Control-Allow-Origin: *`

**Отдельно:** `Eye/Dashboard.tsx` и `Eye/TelemetryDock.tsx` — **мёртвый код**
(нет `package.json`, `tsconfig.json`, бандлера; ноль `fetch`/`EventSource`).
Строить Mini App «на базе TelemetryDock.tsx», как предлагает спецификация,
невозможно без введения полного JS-тулчейна. Решение — либо удалить `.tsx`,
либо осознанно вводить сборку. Это отдельная задача, не часть Mini App.
