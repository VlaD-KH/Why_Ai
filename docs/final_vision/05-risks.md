# 05 — Реестр рисков и открытые решения

Риски отсортированы по тому, насколько тихо они проявляются. Тихий отказ на
критичном пути опаснее шумного отказа где угодно.

---

## R-01 · Ложное подтверждение остановки системы 🔴 КРИТИЧЕСКИЙ

**Суть.** Спецификация вызывает `POST /api/control/panic` — маршрута не
существует. Ответ 404 **не проверяется**, оператору отправляется
«🚨 Инициируется Exit Code 10», функция возвращает `"PANIC_SIGNAL_PROPAGATED"`.

**Почему это худший класс отказа.** Оператор нажал рубильник, получил
подтверждение и ушёл. Система продолжает работать. Симптома нет до момента, когда
последствия уже наступили — ровно тот сценарий, против которого затевалась
внеполосная консоль.

**Митигация:** TASK-TG-10 — обязательная проверка HTTP-статуса + тест,
подменяющий эндпоинт на несуществующий и требующий сообщения об **отказе**.

**Остаточный риск.** `Supervisor/launcher.py:121,123` содержит `type="str"`
вместо `type=str` — CLI не запускается вообще (`ValueError: 'str' is not callable`).
Внеполосный рубильник **из командной строки не работает уже сейчас**, независимо
от Telegram. Зона R, чинит человек (TASK Фазы 4).

## R-02 · Утечка учётных данных в публичный репозиторий 🔴 КРИТИЧЕСКИЙ

**Суть.** `github.com/VlaD-KH/Why_Ai` — **публичный**. Спецификация (Часть IV.2)
предлагает вписать литеральный токен бота в `Tool/mcp_config.json`, который
коммитится. Два документа содержат Telegram ID оператора.

**Статус:** утечки не произошло — на момент аудита ни токена, ни ID в
отслеживаемых файлах и в истории нет (проверено `git grep` по всем ревизиям).

**Митигация (выполнено):** оба документа внесены в `.gitignore`.
**Митигация (в плане):** TASK-TG-02/03 — секреты и ID операторов только через ENV.

**Остаточный риск.** Git-история необратима. Один `git add -A` с токеном в
рабочем каталоге — и ротация токена становится обязательной. Правило:
**никогда не коммитить `Tool/mcp_config.json` с реальным значением вместо `${VAR}`.**

## R-03 · Команда `/panic` без авторизации 🔴 КРИТИЧЕСКИЙ

**Суть.** Текущий `handle_incoming_command` (`telegram_connector.py:82-126`)
**не имеет параметра `user_id` вообще** — ни списка операторов, ни проверки.
Одновременно `POST /api/panic` в `Core/server.py:268` не требует аутентификации,
а `do_OPTIONS:89` ставит `Access-Control-Allow-Origin: *`.

Пока коннектор — заглушка, риск теоретический. **В момент подключения реального
транспорта он становится боевым**: кто угодно, дотянувшийся до бота, останавливает систему.

**Митигация:** TASK-TG-03 — авторизация **до** реального транспорта.
Порядок задач в Фазе 1 выбран именно поэтому.

## R-04 · Зелёные тесты, ничего не проверяющие 🟠 ВЫСОКИЙ

**Суть.** `Tool/connectors/*` не содержат ввода-вывода вообще. Существующие тесты
Telegram (`tests/test_mcp_connectors.py:108-121`) сверяют захардкоженные
возвраты: `assertEqual(res["status"], "SENT")`, `assertTrue(res["delivered"])` —
значения, у которых **нет альтернативной ветки**. Такой тест не может упасть.

Аудит суммарно: из 38 тестов профильных файлов **7 реально ограничивают
поведение, 13 слабые, 18 сверяют литерал с литералом**.

**Митигация:** TASK-TG-06 — каждый новый тест обязан быть **наблюдаемо
падающим** до реализации. Анти-критерий: тест не должен проходить против
заглушки, возвращающей константу.

## R-05 · Разрушение инварианта stdlib-only 🟠 ВЫСОКИЙ

**Суть.** Проект действительно stdlib-only (исключение — `yaml` в `try/except`
с fallback) и **не имеет ни одного манифеста зависимостей**. `httpx`, `mcp`,
`pytest` установлены глобально у пользователя — это свойство машины, а не проекта.

Введение `import httpx` требует создания `requirements.txt`/`pyproject.toml` —
**зона I, HIGH, require_human** — и лишает проект свойства «клонировал и запустил».

**Митигация:** транспорт на `urllib.request` (Решение 2 в `02-architecture.md`).

## R-06 · Ложный CRITICAL на каждом прогоне гейта 🟠 ВЫСОКИЙ

**Суть.** Спецификация вызывает `subprocess.run(["pytest", f"{worktree_path}/tests/"])`
**без `cwd=`**. Тесты импортируются от корня репозитория
(`ROOT_DIR = ...parent.parent`, `from Tool.connectors...`), из чужого CWD это даёт
ImportError → `returncode != 0` → ложный алерт CRITICAL и ложный `sys.exit(10)`.

Проект везде использует `unittest`; `Core/server.py:218` запускает его правильно:
`[sys.executable, "-m", "unittest", "discover", ...]`.

**Митигация:** pytest не вводится (см. «Отвергнутые альтернативы»).

## R-07 · Обход политики через зону E 🟡 СРЕДНИЙ

**Суть.** Зона E (`Eye/`) — единственная, где агент пишет автономно. Соблазн
разместить там мост, читающий секреты и открывающий сетевые соединения,
формально пройдёт классификатор, но нарушит основание зоны: «UI/telemetry
carrying no runtime authority of their own».

**Митигация:** мост размещается в `Tool/connectors/` (зона R). То, что это
требует подписи человека, — корректная работа контура, а не препятствие.

**Признак, по которому это ловить в будущем:** если решение выбрано *потому что
оно проходит гейт*, а не потому что оно верное, — это обход.

## R-08 · Слепое пятно измерения объёма 🟡 СРЕДНИЙ

**Суть.** В режиме `--paths` функция `collect_paths()` (`classify_diff.py:314`)
жёстко возвращает `lines_changed = 0`, а проверка порога стоит за
`and lines_changed`. Порог 800 строк **структурно не может сработать** —
классификация по списку путей никогда не видит объём изменений.

**Митигация:** перед коммитом использовать `--worktree`/`--staged`/`--range`,
а не `--paths` (зафиксировано в `04-todo.md`).

## R-09 · Дыры в Конституции 🟡 СРЕДНИЙ

**Суть.** Полнотекстовый поиск по `BIBLE.md`: **нет** принципа о хранении
секретов, **нет** принципа о сетевом доступе из ядра. Требование «Zero PII &
Credentials Leak» существует только в `docs/` — зона E, документы не являются
источником правил.

Практическое следствие: исходящий HTTP из `Supervisor/` блокируется зоной R и
вето кворума, но **не текстом Конституции**. Если зону однажды перенастроят,
запрета не останется.

**Митигация:** Фаза 4, только человек.

## R-10 · Мёртвый код выдаёт себя за основу 🟢 НИЗКИЙ

**Суть.** Спецификация предлагает строить Mini App «на базе `TelemetryDock.tsx`».
Оба `.tsx` — **макеты**: нет `package.json`/`tsconfig.json`/бандлера, ноль
`fetch(`, ноль `EventSource`, ноль `/api/`, состояние захардкожено, Tailwind-классы
без Tailwind, `useEffect` импортируется и не используется.

**Митигация:** Mini App строится как vanilla HTML по образцу работающего
`Eye/dashboard.html`. Судьба `.tsx` — отдельное решение (удалить либо вводить сборку).
