### Звено 4 — почему это не «недоделка», а отсутствие центра

```python
# EvolutionDaemon.py:141-146
changed_files = ["Core/evolution_log.txt", "tests/test_meta_over_patch.py"]
candidate_diff = f"..."   # f-строка с датой
```

`changed_files` — **захардкоженный литерал**. `Core/evolution_log.txt` вообще
не существует. Grep по всему продакшен-коду на
`anthropic|openai|claude|api_key|completion|litellm|ollama|gemini` — **ноль
совпадений**. Песочница создаётся на `:139` и удаляется на `:168`; **между
этим в неё ничего не пишется**.

То есть самоэволюция — это леса вокруг отсутствующего центра. Нечем породить
изменение.

### Звено 6 — нечем применить

`CommitGate.verify_and_merge()` сверяет два SHA-256 (это настоящее) и затем
возвращает литерал `{"status": "MERGED_SUCCESSFULLY"}`. `subprocess`
импортирован на `:14` и **не используется**. «3-Way Merge» существует только
в докстринге.

## 2. Кнопка «Evolve» на дашборде — гарантированный no-op

Проверено запуском:

```
KEYS: ['generated_at', 'steps', 'title']
patterns present? False | total_failures present? False
failures recorded: 3   steps: 3
ВЕРДИКТ без --force: (False, 'IDEMPOTENCY_REJECTED')
```

`IdempotencyGate` (`EvolutionDaemon.py:63-69`) читает `refactor_plan["patterns"]`
и `["total_failures"]`. `generate_refactor_plan()` (`MetaOverPatch.py:98-113`)
эти ключи **не возвращает** — только `{title, generated_at, steps}`.
Три сбоя записаны, три шага сгенерированы, гейт всё равно видит нули и
отклоняет. `Core/server.py:284` вызывает цикл **без** `force`.

Сигнал Meta-over-Patch (Принцип 12) вычисляется и выбрасывается.

## 3. Режимы `[self_evo]` / `[prod_evo]` декоративны

`switch_mode()` (`WorkspaceOrchestrator.py:60-111`) делает две вещи: вызывает
`harden_git_invariants()` — **одинаково для обоих режимов** — и пишет JSON.

Полный список читателей `current_mode`/`topology`/`rank_map`:
`get_current_topology()` (читает свой же файл), `Core/server.py:299-319` (эхо в
HTTP-ответ), тест формы словаря. **Ни один исполняемый путь не ветвится по
режиму.** В `classify_diff.py` слово «mode» встречается дважды — оба раза в
комментарии `failure mode`.

Плюс два несогласованных источника истины: `why_ai_config.yaml:7` говорит
`prod_evo`, `.ai_workspace_state.json` — `project`.

**Следствие для постановки задачи:** строить надо не «self_evo» и не
«prod_evo», а единственный отсутствующий конвейер —
**предложить → изолировать → оценить → применить → записать**. После этого
режим становится параметром политики на конвейере, а не второй архитектурой.

## 4. Почему тесты этого не поймали

- `test_evolution_daemon.py:38` принимает **любой** из четырёх исходов, включая
  провал: `assertIn(status, ("EVOLUTION_CYCLE_SUCCESS", "REJECTED_BY_QUORUM", "MODULE_DISABLED"))`.
- `test_evolution_daemon.py:20` подаёт в гейт **выдуманный** словарь
  `{"patterns": [], "total_failures": 0}` — форму, которую
  `generate_refactor_plan()` никогда не производит. Тест проверяет
  несуществующий контракт.
- `test_commit_gate.py:41` сверяет литерал `"MERGED_SUCCESSFULLY"` с литералом.
- Захардкоженный `changed_files` **подогнан под прохождение собственного
  кворума**: `.txt` не попадает в список код-расширений, а
  `test_meta_over_patch.py` закрывает требование тестов.

## 5. Ouroboros — что там устроено иначе

`github.com/razzant/ouroboros` реален и активен: 1204 звезды, 604 форка, MIT,
v6.109.0, arXiv 2608.08311. Проверено по коду, не по README: вызовы моделей
настоящие (`review_execution.py:365` → `self.llm.chat_async`), путевые гарды
настоящие, привязка коммита к дереву настоящая.

*(Ссылка `codewiki.google/...` из запроса отдаёт пустую страницу — данные взяты
из самого репозитория.)*

| Ось | Ouroboros | Why_Ai |
|---|---|---|
| Предложитель | рефлексия LLM → Pattern Register → структурное LLM-суждение о продвижении | **отсутствует** |
| Изоляция | герметичный префлайт в одноразовом worktree **и** одноразовом data-root | worktree создаётся и удаляется пустым |
| Гейт | 6 слоёв + человек, реальные разные модели | 3 Python-эвристики в одном процессе |
| Применение | `commit_reviewed()`, стейджинг атрибутированной дельты | возврат литерала |
| Память | **вне репозитория**, выделенные write-инструменты | внутри зоны R, писателя нет |
| Режимы | 3 ортогональные оси, каждая читается кодом | 1 ось, не читается ничем |
| Откат | rescue-snapshot + `confirm=true` + рестарт | отсутствует |

### Ключевая идея, которую стоит перенять

**Разделение «предложить» и «опубликовать».** У Ouroboros режим `pro` «может
оставлять правки защищённых путей на диске, но публикация всё равно требует
reviewed-commit-путь».

В Why_Ai `protected_paths.yaml` гейтит **дифф** — то есть агент не может даже
*авторствовать* предложение, затрагивающее `Core/`. **Гейт стоит не на том
конце конвейера.** Именно к этому пользователь подошёл интуитивно, говоря
«в self_evo должно быть право хотя бы предлагать изменения туда, куда доступ
закрыт».

### Вторая ключевая идея — топологическая

**Data-root отдельно от кода** (`~/Ouroboros/repo/` против `~/Ouroboros/data/`).
Это снимает разом две проблемы Why_Ai: `Core/identity.md`, `Core/scratchpad.md`,
`Core/failures.jsonl` лежат **внутри зоны R**, поэтому любая запись в память —
это дифф защищённого кода. У Ouroboros вопрос не возникает, потому что память
физически вне репозитория.

### Чего перенимать НЕ стоит

- **Масштаб.** 1250 файлов и 250+ модулей ядра против ~3000 строк. Копировать
  декомпозицию — карго-культ.
- **Принцип 0 (Agency)** в формулировке Ouroboros: «между безопасным микрофиксом
  и смелой перестройкой выбирай перестройку», «не делает пауз ради одобрения».
  Это прямая противоположность Принципам 2 (fail-closed) и 13 (мержит человек) —
  то есть единственному, что у Why_Ai сейчас действительно работает.
- **Зависимость от Claudexor.** Инвариант stdlib-only — реальный актив.
- **Режим `advisory` enforcement.** Для системы с тремя сбоями и без журнала
  преждевременно.

## 6. Структурный дедлок, который надо решить до запуска

`QuorumReviewer` Class 2 отклоняет код без тестов в том же диффе.
`classify_diff.py` эскалирует дифф, где T и не-T вместе, до `require_human`.

Нормальная единица работы — «код плюс его тест» — **по построению всегда
требует человека**. Нужен либо двухкоммитный протокол, либо явное исключение
для self_evo-полосы. Сейчас это противоречие не разрешено ни в одну сторону.

## 8. Побочные находки

- `QuorumReviewer.py:42` — регистрозависимый `startswith("Supervisor/")`.
  На NTFS путь `supervisor/launcher.py` эту защиту **минует**. У Ouroboros
  этот же обход закрыт явно (таблицы в нижнем регистре).
- `WorkspaceOrchestrator.py:107` и `CommitGate.py:88` — `"updated_at": str(Path.cwd())`:
  рабочий каталог записан в поле времени.
- `remove_sandbox` делает `git branch -D` — ветка отклонённого предложения
  уничтожается, а не сохраняется для разбора.
- Две копии классификатора разошлись: `.ai-loop/bin/classify_diff.py` (642 строки)
  и `Supervisor/classify_diff.py` (487 строк) различаются в 301 строке.
  CI использует первую.
