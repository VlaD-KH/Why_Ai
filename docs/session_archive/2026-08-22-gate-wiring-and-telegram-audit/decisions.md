**Repo `_Ai` vs `Why_Ai`.** Работать только в `C:\Users\Huawei\source\_Ai\Why_Ai`
как в самостоятельном проекте; `_Ai` (родительский репозиторий,
`VlaD-KH/_Ai_`) объявлен нерелевантным. → Не трогать файлы/policy за
пределами `Why_Ai/`, даже если родительский репозиторий физически рядом.

**Способ HTTPS для Telegram Mini App.** Туннель (cloudflared/ngrok), не
хостинг и не Test Environment. → При реализации Фазы 3 разворачивать именно
туннель; `Core/server.py` пока не отдаёт `telegram_mini_app.html` вообще —
маршрута нет (зона R, отдельное решение).

**Судьба `Eye/*.tsx`.** Удалить (`Dashboard.tsx`, `TelemetryDock.tsx`) —
были мёртвым кодом без сборки, 0 реальных вызовов API. Сделано, закоммичено.

**Хук в `Supervisor/launcher.py` для Telegram-алертов.** Отклонён.
Причина: зона R + жёсткое вето `QuorumReviewer.py` по префиксу
`Supervisor/` + Принцип 1 BIBLE. Вместо этого — подписка моста на уже
существующий SSE (`broadcast_event`, `Core/server.py`). Мост
(`Tool/connectors/telegram_bridge.py`) при этом **не реализован** (Фаза 2).

**Порядок работ, 2026-08-22.** Сначала три модуля (Living Identity /
EvolutionDaemon+SIGTERM / Swarm Task-Tree), потом возврат к Telegram Фазе 2.
Из трёх: Living Identity pinning и Multi-Harness Class 1/2/3 уже были
реализованы (проверено); реально не хватало SIGTERM (сделано) и Swarm
Task-Tree (**не сделано** — `/api/swarm/tasks` всё ещё отдаёт выдуманных
агентов).

**Храповики размера (Принцип 10) — Вариант 1.** Подключить `check_file()`
к `CommitGate` **до** запуска self_evo, а не отложить и не убрать принцип.
Обоснование (файл `docs/Вариант 1 check_file() со шлюзом.md`): без
аппаратного гейта агент безнаказанно раздувает код — текстовые инструкции
не держат на длинной дистанции (Action Bias). **Сделано и запушено.**

**Runtime mode (light/advanced/pro), идея из Ouroboros.** В `pro`: писать
на диск можно (даже в `Core/`/`Supervisor/`), но **публиковать — только
через ревью**. Гейт переезжает с «авторства» на «публикацию». **Не
реализовано** — это Фаза 5.3.1, решение зафиксировано, код не писался.

**Data-root агента (identity.md/scratchpad.md/failures.jsonl).** Вынести
за пределы репозитория, как у Ouroboros (`~/.why_ai/data/` по аналогии) —
сейчас они внутри `Core/` (зона R), поэтому запись агента в свою же память
формально является диффом защищённого кода. **Не реализовано.**

**Источник истины о режиме `[self_evo]`/`[prod_evo]` — Вопрос 8.** Только
`why_ai_config.yaml:system.active_mode`. `.ai_workspace_state.json` **не
читается** для этого решения ни в одну сторону — даже если противоречит
YAML. Обоснование: агент может дописать `state.json` через
`switch_mode()`/`POST /api/mode`, но не может отредактировать YAML (зона
R) — если бы решал `state.json`, агент получил бы способ самовольно
включить себе self_evo. **Сделано**: `WorkspaceOrchestrator.resolve_active_mode()`.
Важно: RED-тесты упавшего агента изначально кодировали ПРОТИВОПОЛОЖНЫЙ
контракт (state.json побеждает) — переписаны под это решение, не наоборот.

**ENV-переменные для живой проверки Telegram.** Оператор задаёт сам
(`WHY_AI_TELEGRAM_BOT_TOKEN`, `WHY_AI_TELEGRAM_OPERATORS`, chat_id) —
жду живой проверки. **Открыт вопрос:** сессионная переменная PowerShell не
видна отдельным процессам, которыми я запускаю тесты/скрипты — нужна
пользовательская (`[Environment]::SetEnvironmentVariable(...,'User')`),
если нужна моя проверка, а не только оператора.

**Классификатор — какой канонический.** `.ai-loop/bin/classify_diff.py`
(642 стр., строгое надмножество `Supervisor/classify_diff.py`, 487 стр.) —
имеет `--cumulative`/`--phase`/`--run-id`, которых нет у `Supervisor/`-копии.
Вердикты на 12 проверенных путях совпали побайтово. **Не решено окончательно**
пользователем явно, но по факту сравнения `.ai-loop/bin/` де-факто канон
(его использует CI).

**Telegram ID оператора в документах.** Найден в 3 файлах (не в `.env` —
он пуст; ID пришёл вместе с присланными спецификациями). Все три вычищены
или занесены в `.gitignore`. Репозиторий **публичный** — это правило
навсегда: секреты/ID только через ENV, никогда в файл.
